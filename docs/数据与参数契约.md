# 输入、参数与输出契约

## 输入

`dataset`路径相对于项目根目录；配置文件放在`configs/`。本版输入为已经核实并聚合的地理单元，不自动把任意原始Excel变成合格空间输入。

- `units.csv`：unit_id（从0连续排列）、name、district、market、customers、visits；可附原未知TOP计数字段。三项均非负，统计口径与周期一致。
- `adjacency.csv`：u、v，引用unit_id；包括已经核查的跨江/通行关系，不能单凭面接触认定可通行。
- `boundaries.geojson`：Polygon/MultiPolygon；顺序与units一致，用于展示。南京为WGS84参考面，原坐标转换在上游完成。
- `roads.npz`：SciPy有向稀疏道路图，边权公里；`road_nodes.npz`含street（节点所属单元）、rep_indices（每单元代表道路点）。三个索引体系必须一致。
- `initial_assignment.csv`或用户提供分配：严格字段unit_id、territory_id；辖区编号1～K，各单元唯一完整归属且各组非空。
- `manifest.json`：数据来源、口径、逐文件SHA256。改数据必须新建版本并重新生成清单，不以改哈希来绕过验收。
- `engine.dat*`仅供已固化的研究后端。通用验收不使用它们推断新配置，也不动态改写二进制模型。

## 参数

- `hc`：正整数；验收支持通用K，研究求解当前限8。
- `tolerance`：按market、customers、visits排列，0.2表示每组相对全市均值±20%，不是全市份额20%。
- `distance_cap_km`：组内街道代表点两两有向最短路的最大值上限，不是驻点半径、实际拜访路线或工时。
- `distance_mode`：本版固定induced_directed_road，路径不能借用其他辖区的道路节点。
- `search_seconds`：研究后端每次搜索整数秒；输入加载之外的起点路由验证、缓存与搜索均计入该后端预算，独立验收另计。
- `objective`：本版研究实现仅支持minimize_maximum_internal_road_span；本字段不能用于声称其他目标已经生效。

## 输出

每个运行目录包含config.json、manifest.json、audit.json、assignments.csv、territories.csv、results.xlsx、territories.geojson、report.html。求解运行另含原始分配、初始分区、引擎元数据和日志。

审计必须独立报告：平衡通过、街道连通、代表点道路通达、距离上限、最终合格；结果中“可行”和“严格改善起点”分开。

manifest记录项目版本、代码哈希、配置哈希、输入来源与版本、输入分配文件哈希、方法/种子/预算/研究程序哈希。solve中的assignment_sha256对应输入起点文件，不是返回候选的摘要；当前未逐文件记录全部输出哈希。requirements.lock.txt记录已验证环境，复现实验同时保留该环境清单。
